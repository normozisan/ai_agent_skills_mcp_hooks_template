# プロ品質デザインガイドライン

ui-designer・design-reviewer・implementer が従う共通基準。目的は「AIが生成したと一目で分かるデザイン」を排除し、プロのデザイナーが納品した水準にすること。

---

## 1. AIっぽさアンチパターン(禁止事項チェックリスト)

以下に1つでも該当したらデザインレビュー不合格とする。

- [ ] **紫〜青のグラデーション**をヒーローやボタンに使っている(AI生成の代名詞。意図的なブランド判断がある場合のみ例外)
- [ ] **個性のない書体構成**: 見出しも本文もシステムフォント/Interだけで、書体に意図がない
- [ ] **絵文字をUIの装飾・アイコン代わりに乱用**している(🚀✨💡をカードや見出しに並べる等)
- [ ] **同じ形のカードを3列グリッドで並べただけ**の構成が主役になっている
- [ ] **すべてセンター寄せ**で、視線の流れ・非対称のリズムがない
- [ ] **意味のない角丸大盛り+ぼんやりした大きなドロップシャドウ**(浮いているだけで階層を表現していない)
- [ ] **lorem ipsum やプレースホルダー丸出しのダミーテキスト**が残っている
- [ ] **どの製品にも当てはまる汎用コピー**(「あなたの毎日をもっと便利に」等)をそのまま使っている
- [ ] **全要素が同じ大きさ・同じ濃さ**でジャンプ率(大小のコントラスト)がない
- [ ] **ホバー・フォーカス・空状態・エラー状態が未デザイン**(正常系の見た目しかない)

## 2. アートディレクション(最初に決める)

- プロダクトの性格をムードワード3つで言語化する(例: 家計簿なら「安心・軽快・生活感」)。以降のすべての判断はこの言葉に照らして行う。
- 「このアプリらしさ」が出る**シグネチャー要素**を最低1つ仕込む(特徴的な見出し書体、独自のアクセント色の使い方、罫線・数字の見せ方、独特の余白リズム等)。
- 参考にする実在プロダクトの方向性を2〜3特定し、「何を借りて何を借りないか」を明記する。

## 3. タイポグラフィ(デザインの8割はここで決まる)

- **見出しと本文で書体または太さのコントラストを必ず付ける。**
- 日本語UIの推奨ペア例(Google Fonts):
  - 信頼・堅実系: 見出し Noto Sans JP (700) / 本文 Noto Sans JP (400)、英数字に Inter や IBM Plex Sans を併用
  - モダン・柔らか系: 見出し Zen Kaku Gothic New / 本文 Noto Sans JP
  - 個性・エディトリアル系: 見出し Shippori Mincho または Zen Old Mincho / 本文 Noto Sans JP
  - 数字が主役(家計簿・ダッシュボード等): 数値表示に tabular-nums 指定、または IBM Plex Mono / Space Grotesk 系を数値専用に
- タイプスケールを定義する(例: 12 / 14 / 16 / 20 / 28 / 40px)。中間サイズを恣意的に増やさない。
- 日本語本文は `line-height: 1.7〜1.9`、見出しは `1.2〜1.4`。`letter-spacing` は見出しで `0.02em` 程度、本文は基本 0。
- 本文サイズは16px以上(モバイル)。12px未満は補助ラベルのみ。

## 4. カラー

- 構成比の目安 = **ニュートラル90% : ブランド色8% : アクセント2%**。色数を増やすほど素人っぽくなる。
- ニュートラルは**純粋グレー禁止**。ブランド色の色相をわずかに含んだグレー(例: 青系ブランドなら `#F7F8FA`, `#5A6472`)を使うと一気に締まる。
- 背景は真っ白 `#FFFFFF` 一択にしない。ごく薄いトーン(例: `#FAFAF8`)+カード白で階層を作る。
- テキストのコントラスト比: 本文 4.5:1 以上、大きな見出し 3:1 以上(WCAG AA)。
- セマンティック色(成功/警告/エラー)はブランドパレットとトーンを揃えて調色する(素の `red`/`green` を使わない)。
- ダークモードを作る場合は明度反転ではなく再設計する(背景 `#0F1115` 系、彩度を落としたアクセント)。

## 5. 余白・レイアウト

- 4pxまたは8pxグリッドで統一(4, 8, 12, 16, 24, 32, 48, 64...)。恣意的な 13px, 27px を作らない。
- **余白の階層 = 情報の階層**: 関連する要素は近く(8-12px)、セクション間は大きく(48-96px)。均等な余白は構造がない証拠。
- コンテンツ幅: 本文系は最大 65〜75文字/行(日本語なら35〜40文字)。ダッシュボード系は 1200〜1440px 上限。
- 非対称を恐れない。左揃え基調+要所だけセンターの方がプロっぽく仕上がる。

## 6. コンポーネント・形状

- 角丸は**2段階まで**(例: ボタン/入力 8px、カード/モーダル 12-16px)。全部バラバラは禁止。
- 影は「大きく1つ」ではなく**小さく層で**: `0 1px 2px rgba(0,0,0,.05), 0 4px 12px rgba(0,0,0,.06)` のような多層の弱い影+必要なら1pxボーダー併用。
- ボタンは「押せる」と分かる強さを持たせ、プライマリは1画面に1つが原則。secondary/ghost を使い分ける。
- アイコンは1セットに統一(推奨: Lucide / Heroicons / Phosphor のいずれか)。サイズ・線幅を揃える。絵文字をアイコン代わりにしない。
- 入力フォーム: ラベルは常時表示(placeholderをラベル代わりにしない)、エラーは色+文言で。

## 7. 状態のデザイン(プロと素人の分かれ目)

必ず全部デザインする:
- hover / active / focus-visible(キーボードフォーカスリングは消さずにブランド色で再デザイン)
- disabled / loading(スケルトンまたはスピナー、レイアウトシフトさせない)
- **empty state(0件)**: 最重要。イラストか丁寧な誘導文+最初のアクションボタンを置く
- エラー状態(通信失敗・バリデーション)

## 8. モーション

- 目的のあるものだけ動かす(状態変化のフィードバック、出現の文脈づけ)。装飾で動かさない。
- 時間: マイクロインタラクション 120〜200ms、パネル/モーダル 200〜300ms。400ms超は遅い。
- イージング: `cubic-bezier(0.2, 0, 0, 1)`(標準)/ 出現は ease-out 系。linear 禁止(プログレスバー以外)。
- `prefers-reduced-motion` を尊重する。

## 9. プラットフォーム別の要点

### Webサイト(LP・マーケティング)
- ヒーローは「汎用コピー+グラデ背景+ダッシュボードのスクショ」構成を避ける。実際の価値が伝わる具体的コピーとビジュアルを作る。
- スクロールのリズム(セクションごとの背景トーン交互、幅の変化)で単調さを消す。

### Webアプリ(ツール・ダッシュボード)
- 密度を意識的に選ぶ(ゆったり consumer 系 / 高密度 pro 系)。中途半端が一番悪い。
- テーブル・数値は右揃え+ tabular-nums。行の zebra より hover ハイライト+区切り線薄めが現代的。

### スマホアプリ / モバイルWeb
- タッチターゲット最小 44×44px、主要アクションは画面下部(親指圏)に。
- セーフエリア(ノッチ・ホームバー)を尊重: `env(safe-area-inset-*)`。
- 1画面1タスク。デスクトップUIの縮小版にしない。

## 10. 実装時の技術ルール(implementer向け)

- デザイントークンは必ずCSS変数(`:root { --color-... }`)で実装し、コンポーネントから直接HEXを書かない。
- フォント読み込みは `font-display: swap`、日本語フォントはサブセット版(Google Fonts の text= またはNoto Sans JPの標準サブセット)を使う。
- Tailwind使用時は `tailwind.config` にトークンを登録して使う。任意値(`text-[13px]`)の乱用禁止。
- 画像・イラストが必要な箇所は、CSSグラデ+図形やSVGで質感を作るか、シンプルな自作SVGイラストにする(フリー素材の寄せ集め感を出さない)。

## 11. 最終セルフチェック(納品前)

1. 3秒間見て「どんな性格のプロダクトか」が伝わるか(ムードワードと一致するか)
2. セクション1のアンチパターンに1つも該当しないか
3. 実データ相当のコンテンツで確認したか(長い名前、0件、巨大な数値)
4. モバイル幅(375px)で崩れ・横スクロールがないか
5. キーボードだけで主要フローを操作でき、フォーカスが見えるか
