# UIデザインフェーズ

要求仕様を入力として、プロのデザイナーが作ったと見える水準のデザイン仕様を作成する。成果物は `docs/03_ui_design.md` と、ブラウザで確認できる `docs/design_preview.html`。

ユーザーからのデザイン要望: $ARGUMENTS

## 大原則

このスキル内の `references/design-guidelines.md` を最初に読むこと。このフェーズおよび後続の実装は、そこに定義されたプロ品質基準と「AIっぽさ」アンチパターンチェックリストに全面的に従う。

## 手順

### 1. 入力の確認

- `docs/02_requirements.md` を読む(画面一覧・ペルソナ・非機能要件)。ない場合は先行フェーズの実行をユーザーに確認する。
- `docs/01_market_research.md` があれば読む(差別化ポイント・競合のデザイン傾向がアートディレクションの根拠になる)。
- プラットフォーム(Webサイト / Webアプリ / スマホアプリ)を要求仕様から特定する。

### 2. アートディレクション案の作成(ui-designer サブエージェントに委譲)

ui-designer に要求仕様・市場調査・ユーザーのデザイン要望を渡し、**方向性の異なるアートディレクション案を3つ**作らせる(例: 「ミニマル×信頼」「温かみ×手書き感」「大胆×コントラスト」)。各案にコンセプト名・ムードワード・フォント・パレット(HEX)を含めること。

### 3. 方向性の決定(ユーザーへの確認)

3案を選択肢として提示し、ユーザーに選んでもらう(各案の説明にムード・色・フォントを記載)。
(`--auto` モードの場合: ペルソナと差別化ポイントに最も適合する案を自分で選び、選定理由を成果物に記録する。)

### 4. デザイン仕様書の作成(ui-designer サブエージェントに委譲)

選ばれた方向性で、ui-designer にデザイン仕様書を作らせて `docs/03_ui_design.md` に保存する:
- 入力: 決定した方向性、`docs/02_requirements.md` の画面一覧、テンプレート このスキル内の `templates/ui-design-template.md`、ガイドライン このスキル内の `references/design-guidelines.md`
- デザイントークンはそのままCSS変数として実装に貼れる形式で書かせる

### 5. デザインプレビューの生成(ui-designer サブエージェントに委譲)

`docs/design_preview.html` を作らせる。要件:
- 自己完結型HTML1ファイル(JSフレームワーク不使用。フォントはGoogle Fonts可)
- 内容: ①デザイントークン一覧(色見本・タイポスケール・余白) ②主要画面2〜3枚の静的モック(実データ相当のダミーコンテンツ。lorem ipsum禁止) ③モバイル幅表示の確認ができること

生成されたら、**自分(メインエージェント)が** Playwright MCP でプレビューHTMLを開き、デスクトップ幅とモバイル幅でスクリーンショットを撮って確認する。崩れやガイドライン(セクション1のアンチパターン)違反があれば ui-designer に修正させ、問題がなくなるまで繰り返す。

### 6. 完了報告

ユーザーに報告する:
- 決定したアートディレクション(コンセプト・ムードワード・主要色・フォント)
- `docs/design_preview.html` をブラウザで開いて確認できること
- 次のステップ: `/implement`(実装はこのデザイン仕様に従って行われる)

プレビューを見たユーザーから修正要望があれば、仕様書とプレビューの両方に反映してから次フェーズへ進む。
