# 実装品質ガイドライン

architect / implementer / code-reviewer と実装フェーズが従う品質基準。

## 1. 不合格条件チェックリスト(コードレビューで機械的に確認)

### セキュリティ
- [ ] ユーザー入力を検証せずに使っている(型・長さ・範囲・形式)
- [ ] `dangerouslySetInnerHTML` / `innerHTML` / `eval` に未サニタイズの値を渡している(XSS)
- [ ] APIキー・パスワード等の秘密情報がコードにハードコードされている
- [ ] SQLやコマンドを文字列連結で組み立てている(インジェクション)
- [ ] localStorage に機微情報(パスワード、トークン)を平文保存している

### 堅牢性
- [ ] 異常系が未処理: 空入力、null/undefined、0件、最大長超過、不正な型、重複送信
- [ ] 非同期処理のエラーハンドリングがない(fetch失敗、JSON parse失敗)
- [ ] 保存データの読み込みで、壊れたデータ・旧バージョンのデータを想定していない
- [ ] 浮動小数点で金額計算している(通貨は整数(最小単位)で扱う)

### 型・構造
- [ ] `any` の乱用、`as` による強引なキャスト
- [ ] マジックナンバー・文字列の直書き(定数化されていない)
- [ ] 1ファイル/1関数が肥大化(目安: 関数50行超、ファイル300行超で分割を検討)
- [ ] コピペによる重複ロジック

## 2. アーキテクチャ原則(architect向け)

- **MVPに必要な最小構成**にする。「後で使うかもしれない」層・抽象・ライブラリを入れない
- 状態管理は最小から: React なら useState/useContext で足りるうちは外部ライブラリを入れない
- データ永続化はまず localStorage / IndexedDB / SQLite の最小構成。スキーマにはバージョン番号を持たせ、将来のマイグレーションに備える
- 依存ライブラリを1つ増やすごとに「自作なら何行か」を自問する(20行で書けるものにライブラリを入れない)
- ロジック(計算・変換・検証)はUIから分離した純関数にする(=ユニットテスト可能にする)

## 3. 実装原則(implementer向け)

- **タスクを小さく完結させる**: 1タスク終了時点で必ずビルドが通る状態にする
- ライブラリAPIは記憶で書かない。Context7 MCP または公式ドキュメントで確認してから書く
- UIはデザイン仕様のCSS変数(トークン)のみ使用。HEX直書き・恣意的なpx指定は禁止
- エラーはユーザーに見える形で処理する(黙って握りつぶさない。console.logだけで済ませない)
- コメントは「コードから読み取れない理由・制約」のみ。何をしているかの説明コメントは書かない
- 識別子は英語、UIテキスト・エラーメッセージは日本語で丁寧に(「エラーが発生しました」で済ませず、何をすればよいか書く)

## 4. アクセシビリティ実装の最低ライン

- ボタンは `<button>`、リンクは `<a>`(divにonClickをつけない)
- 全ての入力に `<label>` を関連付ける
- 画像・アイコンボタンに代替テキスト(`alt` / `aria-label`)
- キーボードのみで主要フローが完遂できる(Tab順、Enter/Escape)
- フォーカスリングを消さない(デザイン仕様に従い再デザインは可)

## 5. パフォーマンスの最低ライン

- リストは安定した `key` を使う(indexをkeyにしない)
- 重い計算はメモ化 or イベント時のみ実行(毎レンダリング実行しない)
- 画像は適切なサイズで(元画像をCSSで縮小表示しない)
- 初期バンドルを不必要に太らせない(重いライブラリの安易な導入禁止)
