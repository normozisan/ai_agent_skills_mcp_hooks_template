# 一気通貫パイプライン

アイデア1つを入力に、市場調査 → 要求仕様 → UIデザイン → 実装 → テスト の5フェーズを順に実行し、動くアプリと全ドキュメントを完成させる。

入力: **$ARGUMENTS**

## 実行モードの判定

- `$ARGUMENTS` に `--auto` がある場合: **自動モード**。各フェーズの意思決定はユーザーに質問せず、入力情報と CLAUDE.md の既定値から合理的に判断して進める。判断内容は各成果物の「要確認事項」に記録する。
- それ以外: **対話モード**。各フェーズの節目で重要な意思決定のみユーザーに確認する。
- `$ARGUMENTS` に `--spec` がある場合: **仕様持ち込みモード**。フェーズ1(市場調査)をスキップし、渡された仕様書からフェーズ2を開始する。
- アイデアも仕様も空の場合はユーザーに確認する。

## 途中からの再開

開始前に `docs/` の既存成果物を確認する。`01`〜`06` の成果物が既に存在する場合は、**完了しているフェーズをスキップして続きから再開する**のを既定とする(各フェーズの完了ゲートを満たしているか検証してから)。ただし:
- アイデアが前回(`docs/00_idea.md`)と明らかに異なる場合は、最初からやり直すか確認する
- 対話モードでは「どのフェーズから再開するか」を提示して確認する。自動モードは検証済みの続きから黙って再開する

## 実行手順

※ 各スキルの実行は、スキル呼び出し機能があればそれで行い、無い環境では該当スキルの `SKILL.md` を読んでその手順に従う。

開始時にToDoリスト(利用可能なタスク管理ツール)で5フェーズのタスクを登録し、進捗を可視化する。アイデア(仕様持ち込みモードでは仕様の概要と所在)を `docs/00_idea.md` に保存してから開始する。

### フェーズ1: 市場調査(仕様持ち込みモードではスキップ)

`market-research` スキルをアイデアを引数にして実行する。
- **完了ゲート**: `docs/01_market_research.md` が存在し、ペルソナ・競合分析・差別化ポイントが埋まっていること。
- 市場調査の結果、アイデアの市場性が著しく低いと判明した場合: 自動モードでも一旦停止し、調査結果とピボット案を提示してユーザーの判断を仰ぐ(唯一の例外)。
- **仕様持ち込みモード**: このフェーズは実行しない(ユーザーが市場調査も欲しいと明示した場合のみ実行)。

### フェーズ2: 要求仕様

`requirements` スキルを実行する(自動モードなら引数に `--auto` を、仕様持ち込みモードなら `--spec` と仕様の内容を伝える)。
- **完了ゲート**: `docs/02_requirements.md` が存在し、全Must要件に受け入れ基準があること。

### フェーズ3: UIデザイン

`design` スキルを実行する(自動モードなら `--auto`)。
- **完了ゲート**: `docs/03_ui_design.md` と `docs/design_preview.html` が存在し、デザイントークン・全画面の仕様・空状態/モバイル仕様が埋まっていること。

### フェーズ4: 実装

`implement` スキルを実行する(自動モードなら `--auto`)。
- **完了ゲート**: `app/` でビルドが通り、code-reviewer のレビューで Critical/High がゼロ、かつ design-reviewer のデザインレビューが合格であること。
- implement 側の修正ループ上限(コードレビュー2周・デザインレビュー3周)で達成できなかった場合は、自動モードでも停止して残課題を提示し、ユーザーの判断(妥協して続行/追加修正)を得てから次フェーズへ進む。

### フェーズ5: テスト

`test-app` スキルを実行する。
- **完了ゲート**: `docs/06_test_report.md` が存在し、テストが実行済みであること(全パスが理想。失敗が残る場合は理由がレポートに明記されていること)。

## フェーズ間の共通ルール

- 各フェーズ開始前に前フェーズの成果物を検証する。完了ゲートを満たしていなければ、そのフェーズ内で修正してから次へ進む。
- 途中でエラーやツール失敗が起きても、原因を調査して自力でリカバリする。同じ失敗が3回続いた場合のみ状況を整理してユーザーに報告する。
- 各フェーズ完了時に1〜3行の進捗サマリーをユーザー向けに出す。

## 最終報告

全フェーズ完了後、以下をまとめて報告する:

1. **完成したもの**: アプリの概要と起動方法(`cd app` してから `npm run dev`)
2. **成果物一覧**: docs/00〜06 の各ファイルと design_preview.html へのリンク
3. **品質状態**: コードレビュー結果、デザインレビュー結果、テスト結果サマリー
4. **残タスク・次の一手**: 既知の課題、MVP後の機能候補(Should要件)
5. **この先の使い方**: 機能追加・修正は `/iterate <変更内容>`、公開準備は `/release` でできること
