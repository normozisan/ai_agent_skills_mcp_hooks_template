# テスト品質ガイドライン

test-engineer とテストフェーズが従う品質基準。目的は「通るだけで何も守っていないテスト」を排除すること。

## 1. 不合格条件チェックリスト

- [ ] Must 要件のうちテストケースが1つもないものがある
- [ ] 正常系しかテストしていない(境界値・異常系ゼロ)
- [ ] アサーションのないテスト、または「エラーにならないこと」しか確認しないテストがある
- [ ] テストが実装の内部構造(関数の呼び出し回数、内部状態)に依存していて、リファクタで壊れる
- [ ] E2Eテストが `waitForTimeout`(固定待ち時間)に依存している(フレーキーの温床)
- [ ] テスト間に依存関係がある(順番を変えると落ちる、前のテストのデータを引き継ぐ)
- [ ] 失敗したテストを「とりあえずskip」して残している(理由の明記なしに)

## 2. テストピラミッド(配分の目安)

- **ユニットテスト(多)**: `lib/` の純関数(計算・検証・変換)を網羅する。境界値はここで徹底的に(実行が速く安い)
- **E2Eテスト(少)**: ユーザーストーリーの主要フローを数本。「記録して→一覧で見えて→リロードしても残る」のような一気通貫シナリオ
- UIコンポーネントの細部(マージン、色)はテストコードで固めない(design-reviewerの領分)

## 3. 良いテストの書き方

- **AAA構造**: Arrange(準備)→ Act(実行)→ Assert(検証)を明確に分ける
- テスト名は仕様として読めるように: `test('金額が0円のとき保存ボタンが無効になる')`(「test1」「正常系2」は禁止)
- 1テスト1検証事項。落ちたときに何が壊れたか名前だけで分かるように
- テストデータは意図が分かる値にする(`amount: 999999999` は上限テスト、`name: 'あ'.repeat(51)` は長さ超過テスト)

## 4. Playwright E2E の原則

- セレクタ優先順: `getByRole` > `getByLabel` > `getByText` > `getByTestId`。CSSクラスセレクタは禁止(デザイン変更で壊れる)
- 待機は自動待機とweb-first assertion(`await expect(locator).toBeVisible()`)に任せる。`waitForTimeout` 禁止
- 各テストは独立して実行可能に(beforeEachで状態リセット。localStorageのクリア等)
- モバイル幅(viewport 375px)のテストを最低1本入れる

## 5. 境界値の定番セット(全入力フィールドで検討)

| 種類 | テストする値 |
|---|---|
| 数値 | 0、1、-1、最大値、最大値+1、小数、全角数字 |
| 文字列 | 空文字、1文字、最大長、最大長+1、絵文字、HTMLタグ(`<script>`)、前後空白 |
| 一覧 | 0件、1件、大量(1,000件) |
| 日付 | 今日、過去、未来、月末、うるう年2/29 |
| 操作 | 連打(二重送信)、入力途中の画面遷移、リロード直後 |

## 6. 失敗時の切り分け手順

1. テストコードの問題か、アプリのバグかをまず切り分ける(期待値が仕様と合っているか `docs/02_requirements.md` で確認)
2. アプリのバグなら: 再現条件を最小化 → 該当要件IDを特定 → 修正提案(または implementer へ委譲)
3. **テストを仕様に合わせて弱めることで「直す」のは禁止**(仕様側が間違っている場合はユーザーに確認)
