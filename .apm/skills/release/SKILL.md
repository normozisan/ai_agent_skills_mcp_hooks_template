# リリースフェーズ

テスト済みのアプリを「他人に渡せる・公開できる」状態にする。成果物は `docs/07_release.md` とリリース可能なビルド。

デプロイ先の希望: $ARGUMENTS

## 手順

### 1. リリース前チェックリスト(すべて確認し、結果を記録)

- [ ] `docs/06_test_report.md` が存在し、判定が「合格」または残存リスクが許容済みであること(不合格のままならユーザーに確認)
- [ ] `npm run build` が警告なしで成功する
- [ ] 本番ビルドをプレビュー(`npm run preview` 等)で起動し、Playwright MCPで主要フローを1周確認する(開発サーバーでしか動かない問題の検出)
- [ ] console にエラー・警告が出ていない
- [ ] デバッグ用コード(console.log、テストデータの自動投入、TODO)が残っていない
- [ ] 秘密情報(APIキー等)がビルド成果物に含まれていない
- [ ] favicon・タイトル・OGP(公開Webの場合)が仮のままになっていない
- [ ] 404・オフライン・初回起動(データ0件)の状態が壊れていない

**SaaSガイドライン適用アプリの場合**、`${CLAUDE_PROJECT_DIR}/.claude/skills/implement/references/saas-guidelines.md` セクション8の追加チェック(本番シークレット分離、Webhook本番登録、RLS全テーブル有効、規約・特商法表記の公開、エラー監視)もすべて確認する。

問題があれば修正してから次へ進む(修正は implementer に委譲可)。

### 2. アプリ用READMEの生成

`app/README.md` を、実装されたアプリの実態に合わせて書き直す: アプリ概要 / スクリーンショット相当の説明 / セットアップ手順 / 使い方 / 技術スタック / テスト実行方法。

### 3. デプロイ準備

デプロイ先をユーザーに確認する(AskUserQuestion。希望が $ARGUMENTS にあればそれに従う):

- **静的Webアプリ(バックエンドなし)**: GitHub Pages / Netlify Drop(アカウント不要度が高い順に提案)
- **Vercel / Netlify(CLI)**: CLIでのデプロイ手順を用意(実行はユーザー承認後)
- **ローカル配布のみ**: ビルド成果物と起動手順の説明

選ばれた方式に必要な設定ファイル(`vite.config` の base パス、リダイレクト設定等)を実装し、ビルドが通ることを確認する。

**注意**: 実際のデプロイ(外部公開)はユーザーの明示的な承認を得てから実行する。アカウント認証が必要な操作はユーザーに手順を案内する。

### 4. リリースノート作成

`docs/07_release.md` に保存: バージョン / チェックリスト結果 / デプロイ方式と手順(再現可能な粒度) / 公開URL(あれば) / 既知の問題 / 次バージョン候補(要求仕様のShould要件から)。

### 5. 完了報告

チェックリスト結果、公開URL または起動手順、今後の改修は `/iterate` で行えることを報告する。
