# AIユーザー評価ループ(user-test)

ペルソナを演じるAIユーザーがアプリを実際に操作・採点し、合格ラインまで「評価→改善→再評価」を回す。`/refine` の数値改善ループのUX版。

引数: $ARGUMENTS(合格ライン既定 16/20、ラウンド上限既定 3)

## 1. 評価設計の確定(ループに入る前に)

- **前提確認**: `app/` が存在し起動できること(無ければ先に `/poc` または `/implement` を案内)
- **ペルソナ**: `docs/01_market_research.md` → 無ければ `docs/poc/00_poc_spec.md` → どちらも無ければユーザーに確認
- **主要タスク3つ**: 仕様(POC仕様のMust機能 or `docs/02_requirements.md` のユーザーストーリー)から「ペルソナが日常で必ず行う操作」を3つ抽出する(例: 記録する/見返す/修正する)
- 評価設計(ペルソナ・タスク・合格ライン・上限)を1画面でユーザーに提示して確定する(`--auto` や /goal 配下の無人実行では自動確定し、記録に明記)

## 2. 評価ラウンド(user-simulator サブエージェントに委譲)

user-simulator に以下を渡して評価させる:
- アプリの起動方法(`app` フォルダで `npm run dev` 等)とURL
- ペルソナの要約、主要タスク3つ
- 出力テンプレート: `${CLAUDE_PROJECT_DIR}/.claude/skills/user-test/templates/user-eval-template.md` のパス
- 「コードは読まず、実操作のみで採点」の念押し

## 3. 判定と改善

- **合格ライン到達** → 終了(手順4へ)
- **未達** → 不満点リストの**深刻度上位2件だけ**を改善する:
  - UI調整・文言・導線の修正 → implementer に直接委譲
  - 仕様・機能に関わる変更 → `/iterate` の手順で(仕様書への反映込み)
  - **1ラウンドの改善は2件まで**(直しすぎて別物にしない。他の不満は次ラウンドに持ち越し)
- 改善後、手順2の再評価へ

## 終了条件(いずれか)

1. 合計点が合格ラインに到達
2. ラウンド上限(既定3回)に到達
3. 前ラウンドから合計点が上がらなかった(頭打ち。改善が空回りしている)

## ガードレール

- **スコアのために機能を削らない・タスクを簡単なものにすり替えない**(評価条件は全ラウンド固定)
- 改善のたびに既存テストを実行し、壊していないことを確認する
- user-simulator の採点に主観で上乗せ・割引をしない(採点はエージェントの返答をそのまま記録)

## 4. 記録と完了報告

`docs/09_user_eval.md` に保存: 評価設計 / ラウンドごとの採点推移表 / 各ラウンドの不満点と改善内容 / 最終判定(合格・上限・頭打ち)/ 残っている不満点。

報告の最初の1行は「合格(スコア)/ 未達(スコア、理由)」。そして必ず次を添える: **AIユーザーの評価は実ユーザーの代用ではない。** このループは「実ユーザーに見せる前の粗取り」であり、仮説検証は実際のユーザーで行うこと。
